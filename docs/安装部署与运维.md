# Dual-Gateway 安装部署与运维手册

> 适用版本 v1.0.0。本文覆盖**裸机/二进制**安装、配置、启动、日常运维与调优。
> 容器化（Docker / Docker Compose / Kubernetes）部署见同目录《Docker-K8s部署说明.md》。

## 1. 环境要求

| 组件 | 要求 | 说明 |
|---|---|---|
| Go | ≥ 1.26 | 编译用；运行时为纯静态二进制（CGO 关闭） |
| OS | Linux（生产）/ Windows/macOS（开发） | 生产建议 Linux |
| Redis | 6.x/7.x，可选 | 在线态/影子/指令队列；不连则自动降级本地内存 |
| Kafka | 可选 | 业务事件转发；不连则自动丢弃计数 |
| 内存 | 生产 ≥ 8 GB | 单机 5 万在线约需 6 GB |

**端口规划（每进程）**

| 端口 | 协议 | 用途 |
|---|---|---|
| 8080 | TCP | C 端 WebSocket |
| 5683 | UDP | IoT MQTT-SN 明文 |
| 5684 | UDP | IoT DTLS-PSK |
| 5685 | UDP | IoT MQTT-SN over QUIC |
| 9090 | TCP | /health、/metrics、/admin |

## 2. 编译

```bash
cd dual-gateway

# 主程序
go build -o build/gateway ./main/gateway

# 压测工具（admin 后台一键验收/压测依赖）
go build -o build/tokengen.exe ./test/loadtest/tokengen    # Linux 去 .exe
go build -o build/cend_loadtest ./test/loadtest/cend
go build -o build/iot_loadtest  ./test/loadtest/iot
```

> Windows 下二进制带 `.exe` 后缀；admin 后台会按 `runtime.GOOS` 自动追加。

## 3. 准备密钥

C 端 JWT 与 QUIC 证书位于 `config/keys/`：

```bash
# 1) JWT：仓库已自带样例密钥；生产请重新生成
#    网关启动时若密钥无效会自动生成一对 RSA2048（开发态）。

# 2) 批量签发 C 端测试 Token（压测用）
go run ./test/loadtest/tokengen -keys-dir config/keys -count 5000 -out build/tokens_quic.txt

# 3) QUIC TLS 证书：仓库已自带自签证书；缺失时网关启动自动生成，生产请替换为受信 CA 证书。
```

## 4. 配置

主配置 `config/config.yml`，启动时用 `-config` 指定（支持 yaml/yml/json）。关键项：

```yaml
runtime: { max_procs: 20 }          # 建议设为 CPU 核数
cend:
  port: 8080
  max_connections: 100000           # 单实例连接上限，快速失败
  read_buffer_size: 4096            # 高在线量下内存友好
  write_buffer_size: 4096
iot:
  port: 5683
  dtls_port: 5684                   # 0 表示关闭 DTLS
  quic_enabled: true                # 灰度可关
  quic_port: 5685
  worker_count: 2048                # UDP/QUIC 包处理 worker
redis:  { addr: "localhost:6379" }
kafka:  { brokers: ["localhost:9092"] }   # 留空/不可达自动降级
shadow: { enabled: true, offline_ttl_seconds: 120 }
rate_limit:
  connect_rate: 10000               # 每秒握手上限
  udp_per_ip_rate: 10000           # 单源 IP 每秒 CONNECT（防伪造洪峰）
  cend_accept_rate: 5000           # WS accept 节流
```

**环境变量覆盖**：`REDIS_ADDR`、`KAFKA_BROKERS`（逗号分隔）、`LOG_LEVEL`。
> 注意：`GATEWAY_ID` 已在代码中预留但**当前未真正生效**，网关 ID 由 `hostname+pid` 生成；多副本请依赖 K8s 域名/Service 路由，详见部署说明。

## 5. 启动与停止

```bash
# 前台启动
./build/gateway -config config/config.yml

# 后台（systemd / nohup）
nohup ./build/gateway -config config/config.yml > logs/gateway.log 2>&1 &

# 停止：发送 SIGTERM，网关优雅关闭（30s 内排空，影子置离线）
kill -TERM <pid>
```

启动成功标志（日志）：
- `C-end gateway started ... :8080`
- `IoT gateway started ... :5683 workers=2048`
- `IoT QUIC gateway started ... :5685 0rtt=true`（开启时）
- `Monitor server started ... :9090`

## 6. 运维与监控

### 6.1 健康检查
```bash
curl http://127.0.0.1:9090/health
```
关键字段：`cend_conns`（C 端在线）、`iot_devices`/`iot_sessions`（设备/会话）、
`quic_conns`、`iot_packets`、`iot_dropped`（丢包）、`iot_errors`、
`rate_connect_rejected`/`rate_accept_rejected`（限流拒绝）、
`redis_local`（true=Redis 降级）、`kafka_available`、`cmd_enqueued/done`。

### 6.2 指标
```
curl http://127.0.0.1:9090/metrics      # Prometheus 抓取
```

### 6.3 可视化后台
浏览器打开 `http://<host>:9090/admin`：实时总览、单设备影子/指令队列查询、压测任务发起、一键全功能验收。

### 6.4 日常巡检清单
| 检查项 | 判据 |
|---|---|
| `redis_local=true` | Redis 断链，跨节点路由/影子受影响，尽快恢复 |
| `kafka_available=false` | 业务事件只在内存计数，事件会丢，尽快恢复 |
| `iot_dropped` 持续增长 | packetCh 积压，调大 `worker_count` 或扩 UDP 内核缓冲 |
| `rate_*_rejected` 突增 | 遭遇连接洪峰/重连风暴，按现场规模调整限流阈值 |
| 内存随连接线性上涨 | 属正常；按单连接约 20KB(C端)/130KB(QUIC) 估算容量 |

## 7. 性能调优

- **文件描述符**：`ulimit -n 1048576`（长连接必备）。
- **内核参数（Linux）**：
  - `net.core.somaxconn=65535`、`net.ipv4.tcp_max_syn_backlog` 调大（降低突发建连拒绝）。
  - `net.core.rmem_max/wmem_max=67108864`（UDP/QUIC 32MB 收发缓冲需要）。
- **GOMAXPROCS**：`runtime.max_procs` 设为容器/节点 CPU 核数。
- **连接数**：`cend.max_connections` 按单机容量上限设置，超限快速失败。
- **内存**：C 端 `read/write_buffer_size` 在线量大时保持 4KB，避免放大单连接占用。

## 8. 常见问题

| 现象 | 排查 |
|---|---|
| 启动后 `Redis unavailable ... degraded mode` | Redis 未启动；跨节点影子/转发不可用，单机功能正常 |
| QUIC 端口起不来 | 证书/端口冲突；查 `quic_enabled`/`quic_port` 是否与 UDP/DTLS 冲突 |
| IoT 设备被限流拒绝（CONNACK 0x03） | `rate_limit.connect_rate`/`udp_per_ip_rate` 偏低，按现场规模调高 |
| C 端建连被拒 429 | `cend_accept_rate` 节流触发，突发压测请平滑建连 |
| 设备离线但 C 端仍看到在线 | 等待 `offline_ttl_seconds` 或网关已重启（停机已批量置离线） |
